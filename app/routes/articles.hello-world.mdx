## How it all started

My path into technology did not start with modern JavaScript frameworks or AI-assisted coding. It started much earlier with computers, hardware, networking, technical support, and solving problems for people.

I started working in IT in 2002, providing hardware, networking, and website development services. Over the following years I worked across technical support, networking, hardware systems, CCTV, traffic monitoring infrastructure, information security, and IT operations.

That experience taught me something that has stayed with me throughout my career: I enjoy figuring out how things work, finding what is broken, and turning complicated technical problems into practical solutions.

![A collection of technology, networking, hardware, and web development work representing my journey through IT](/static/inspiration.png)

## From IT support to web development

As my career developed, the web became an increasingly important part of what I was doing.

I worked with websites, hosting environments, domains, DNS, servers, migrations, performance, and troubleshooting. WordPress eventually became one of the technologies I worked with most extensively.

I learned by building real websites, maintaining them, fixing them when they broke, moving them between hosting environments, improving their performance, and solving the problems that appeared along the way.

That practical experience eventually became a major part of my professional identity.

I worked as a WordPress Developer at Letdel Group, provided freelance WordPress and IT solutions through Upwork, and later joined TRIAD as a WordPress Developer and IT Support Specialist.

At TRIAD, my work covers both sides of technology: developing and maintaining websites while also supporting the organization's systems, hardware, networks, hosting, and technical infrastructure.

![A collection of websites and digital projects representing my WordPress development work](/static/triad-mockups.png)

## Building this portfolio

This portfolio is different from the business websites I normally build.

Instead of treating it as just another website, I wanted to use it as a place to experiment.

I wanted to explore modern React development, interactive interfaces, animation, 3D experiences, responsive design, and new ways of combining design with development.

The current version is built around React and Remix, with Vite providing the development environment. For animation and interaction I use Framer Motion, while Three.js provides the foundation for the interactive 3D experiences.

CSS Modules are used to keep the styling of individual components isolated and maintainable.

The project has also become a way for me to explore technologies that are outside the traditional WordPress ecosystem I have worked in for many years.

- The site is built with React and Remix, giving me a modern component-based application architecture.
- Styling uses CSS Modules together with modern CSS techniques for responsive layouts and visual effects.
- Framer Motion is used for animation and interactive transitions.
- Three.js is used for 3D graphics and interactive visual experiences.
- Vite provides the development and build tooling.
- AI-assisted development has become an important part of my workflow, helping me explore ideas, prototype solutions, debug problems, and move from an idea to a working implementation much faster.

## Not just coding

Although development is now an important part of my work, I don't see myself as someone who only writes code.

My background is much broader.

I have worked with hardware, networks, servers, hosting, domains, DNS, security, CCTV systems, technical support, and websites. That background changes the way I approach development because I naturally think about the entire system rather than only the code inside a single application.

When a website has a problem, I don't necessarily assume that the problem is in the website itself.

It could be DNS.

It could be hosting.

It could be SSL.

It could be a server configuration.

It could be a third-party service.

It could be a network problem.

Or it could simply be a bug in the application.

Having experience across these areas has helped me become comfortable troubleshooting problems from different directions.

## Learning full-stack development

After many years of practical IT and WordPress experience, I wanted to expand my development skills beyond the WordPress ecosystem.

I completed the IBM Full Stack Software Developer certification as part of that transition.

The goal wasn't to abandon WordPress. WordPress remains an important part of my professional experience.

Instead, I wanted to understand more of what happens underneath the tools I had been using for years and become more comfortable building modern web applications from the ground up.

That meant learning more about application architecture, frontend development, backend concepts, APIs, databases, development tooling, and modern JavaScript-based workflows.

This portfolio is one of the places where I continue applying that knowledge.

## Learning UI/UX

Development is only one side of building a good digital experience.

I'm also continuing to develop my UI/UX knowledge through Google's UX Design program.

Figma and Photoshop are already part of my creative workflow, but studying UX has helped me think more deliberately about the relationship between visual design, usability, interaction, accessibility, and the people actually using the product.

I don't want to simply build something that works.

I want to understand why it should work that way and how the experience can be made clearer, more useful, and more enjoyable.

## Working with AI

One of the biggest changes in my development workflow has been the rise of AI-assisted development.

I don't consider AI a replacement for understanding technology.

I use it as a development and creative partner.

I can start with an idea, experiment with different approaches, investigate an unfamiliar technology, generate a prototype, troubleshoot an error, compare solutions, and iterate much faster than I could before.

This portfolio has become one of the projects where I experiment heavily with that workflow.

Sometimes that means writing code myself.

Sometimes it means using AI to generate a first implementation.

Sometimes it means debugging something that AI generated.

And very often it means going back and forth between the two until the result actually works.

The important part for me is still the same thing that motivated me when I started working in IT: understand the problem, experiment with solutions, and make the technology do something useful.

## Not all smooth sailing

Building this site has definitely not been a straight line.

I've had to deal with dependency conflicts, build configuration problems, browser differences, responsive layout issues, WebGL behaviour, animation preferences, image loading, development tooling, and the countless small problems that appear when different technologies have to work together.

Some problems were simple.

Others required much more investigation.

That is actually one of the reasons I enjoy maintaining this project.

Instead of hiding the technical problems, I treat them as part of the learning process.

The portfolio is not only a finished visual product. It is also an ongoing experiment in how modern web technologies behave together.
